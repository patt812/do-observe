# Cloudflare Durable Objects 実測SLA（第2版・2026-08-05）

**観測条件**: クリーン計測67.9時間（2.83日、2026-08-02 14:01 JST〜）、11 DO（1本×6 / 100本×4 / 5000本×1）計5,406接続、国内VPS観測、意図的kill除外済み。死亡判定は世代ID基準（クライアント側事象に汚染されない）。

## 1. DO死亡（CF起因の強制再作成）— 信頼度: 高

| 指標 | 実測値 |
|---|---|
| 死亡率 | **2.28回/DO/日**（71件 / 31.1 DO日） |
| 日別変動 | 23件(日) / 27件(月) / 21件(火) — 平日・週末で差なし |
| 接続数依存 | 1本=2.36 / 100本=2.12 / 5000本=2.48 回/DO/日 — **無相関** |
| 復旧（切断検知→新世代で受信再開） | **p50 0.47s / p90 1.06s** / p99 19.8s（悪い裾はクライアント側嵐と重複、下記注記） |
| 同時死 | ほぼ常に1台ずつローリング。最短2秒差のペアを1回観測（同一ホスト隣接と推定） |
| colo移行 | 未観測（全件同一colo内の再作成） |
| 死の署名 | **全件無言**（closeフレーム/EOFなし）。検知手段はハートビート途絶のみ |
| 発生時間帯 | 特定の窓なし（深夜波もあれば昼の波もある。「更新イベント駆動」） |

**視聴者インパクト換算**（1秒ハートビート・k=3・即時再接続・seq追いつき実装時）:
- 1回の死亡 = **4〜6秒のコメント停止→自動追いつき**（欠損ゼロ）。チューニング(k=2)で2.5〜3秒
- シャード可用性 ≒ **99.98%**（停止約14秒/日/シャード）
- 2時間配信中に自シャードの死に遭遇する確率 ≒ **17%**

## 2. 個別WS切断（DO生存・経路/エッジ起因）— 信頼度: 中

- 静穏時ベースライン: **1接続あたり約0.3回/日**、復帰1〜2秒
- メンテ集中期は3〜5倍化し、同一エッジ機に載る束（10〜110本、複数DO横断）が同時に切れる
- **注記**: 「実エッジ束切断 → 再接続ラッシュ → DOのupgradeシェディング → バックオフ深化」という増幅ループにより、嵐の時間帯はクライアント計測の切断数・復帰時間が実態より悪化して見える。死亡カウントには影響しない。増幅の定量分離は調査継続中

## 3. このSLAが成立する前提（クライアント/サーバー設計要求）

1. **配信中は毎秒ハートビート**（コメントゼロでも送る。outgoing無課金）
2. **検知は「間隔×3」タイムアウト**（無言死のため受信途絶監視が唯一の手段）
3. **復帰後グレース**（接続確立から15秒はタイムアウトを8秒に緩和）— 二次フラップの自励振動を防止（実測で発生数1/2500に）
4. **即時再接続＋失敗時指数バックオフ**（初回ジッターは0.1〜1秒で十分。5000本の実戦一斉再接続を無事故で吸収済み）
5. **世代ID（storage管理）＋seqによる死の判別と追いつき**

## 4. 主要な実証イベント

- 5000本シャードの実戦死（2026-08-03 16:41 JST）: 4,990本一斉無効化 → 復旧初着0.47秒、輻輳崩壊なし
- ローリング波のフル観測: 11台が数分〜十数分間隔で順に再作成（稼働時間・接続数に無関係、ホスト順と推定）
